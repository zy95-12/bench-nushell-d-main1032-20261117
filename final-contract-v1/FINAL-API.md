# Authoritative final API contract, version 1

This document defines final state only. It applies jointly with the functional specifications; no historical stage, prescribed task DAG or implementation order is required. If duplicate specification wording conflicts with this final API document, this document is authoritative. General public compatibility still applies outside the explicit migrations listed here.

1. Completion metadata belongs to signature `PositionalArg` and `Flag` as `completion: Option<Completion>`. The enum supports `Custom(DeclId)` and static lists (`List(Vec<String>)`); richer description-preserving variants are allowed. Expression nodes do not store completion metadata. Command custom/static completion behavior and variable-annotation rejection are defined by the functional specifications.
2. `src/command_context.rs` provides `pub(crate) fn add_command_context(engine_state: EngineState) -> EngineState`. Callers pass an engine state. No legacy no-argument initializer is required.
3. `stor/insert.rs` uses `fn process(engine_state: &EngineState, table_name: Option<String>, span: Span, db: &SQLiteDatabase, record: Record) -> Result<(), ShellError>`. Preserve other public SQL conversion entry points or provide behavior-preserving wrappers. JSON and JSONB data round-trip requirements remain mandatory.
4. Markdown helpers use `fragment(input: Value, pretty: bool, center: &Option<Vec<CellPath>>, escape_md: bool, escape_html: bool, config: &Config) -> String` and `table(input: PipelineData, pretty: bool, center: &Option<Vec<CellPath>>, escape_md: bool, escape_html: bool, config: &Config) -> String`. Implementations and final-state test clients use these signatures. All specified formatting/escaping semantics apply.
5. SQLite history is publicly available as `nu_cli::SqliteBackedHistory` and implements the `reedline::History` trait. Plaintext history and shared history traits retain their reedline exports. The agreed dependency destination is reedline 0.42 and rusqlite 0.37; history data compatibility/import behavior remains required. Legacy dependency-specific SQLite history export is not required by this final API contract.
6. `PipelineData::empty()` is const. `value`, `list_stream`, and `byte_stream` constructors accept metadata using `impl Into<Option<PipelineMetadata>>`. Existing enum destructuring remains usable.
7. `nu_utils::strings::{SharedString,UniqueString}`, `nu_utils::{SplitRead,NuCow,MultiLife}` are publicly exported with the functional specifications' semantics and layouts. `nu_protocol::value` re-exports MultiLife; the previous split_read module re-exports SplitRead. These are final exports, not task boundaries.
8. Unrelated API compatibility remains required, including the four-argument XML query function, parser parse_block arguments, custom value cell-path operations and experimental test helper support defined in the detailed specs.

Acceptance uses public final-state clients and behavior checks, plus applicable repository regression tests. Historical milestone suites are diagnostic only. Tests are not weakened to accept different behavior: any future semantic change requires a separately versioned public specification. Acceptance coverage gaps and environmental failures must be reported explicitly; a subset pass is not full-roadmap completion.
