# Nushell: a coherent shell and developer-experience evolution

Starting from the supplied Nushell 0.106.0 commit, evolve the project into a more predictable typed shell with better interactive authoring, composable data processing and reusable infrastructure. Deliver working, tested, integrated code, not merely a proposal. This is a multi-area development goal: decide your own work breakdown, dependency ordering, opportunities for parallel work, review and integration. No fixed milestone partition or dependency graph is provided. Preserve valid existing behavior and source compatibility except for the explicit API migrations below. Explain incomplete scope honestly.

## Language correctness and useful type information

Fix external command arguments containing parenthesized subexpressions; argument values and boundaries must be correct. Short flags missing required values must report the offending span. `export def` must not leak parameter names into the enclosing scope. Environment shorthand must not falsely recognize assignments inside escaped quotations. Redefining the builtin `def` must produce a meaningful diagnostic rather than panic. Unbalanced delimiters and incomplete binary operations must report valid, relevant spans rather than empty/garbage expressions. Preserve all currently valid syntax.

Add string-only `not-starts-with` and `not-ends-with` operators, including AST `Comparison::NotStartsWith`/`NotEndsWith`, corresponding string spellings and `Value::not_starts_with`/`not_ends_with` methods, evaluation, `where`, operator completions and `help operators`. Validate `break` and `continue` at compile time: reject them outside applicable loops without breaking legitimate uses; control-flow validation must respect closure/function boundaries. Parse-time row conditions must be type checked.

Pipeline type checking must handle a command with several possible output types for one input type. Carry the set of possible types through the chain, accept compatible continuations, and show multiple possible input types in mismatch diagnostics. Widen list/table literal types correctly for mixed elements and columns rather than retaining an unjustifiably narrow type. Permit variable expressions for table literal column headers. Spreading `null` into a list or record must behave as an empty spread. Power `**` is right associative. Fix bare-string interpolation with subexpressions at both ends. Preserve correct IR evaluation for branched block calls with redirected output. Float equality must be symmetric.

Add an experimental option for runtime enforcement of annotated variable types: mismatching assignments must produce conversion errors with useful spans, while the ordinary mode retains its documented behavior. String and glob types must support compatibility in both directions, and `for` over a range must infer the correct loop-variable type. Implement the option throughout parser/evaluation and tests rather than checking only one surface. Integrate experimental options with the existing CLI and test infrastructure, including `NuOpts.experimental: Option<Vec<String>>`; `nu_run_test()` must append `--experimental-options=[opt1,opt2,...]` and permit `nu!(experimental: vec![...], "command")`.

## Interactive authoring, help and editor integration

Complete local variables while the cursor is inside an unfinished block: function parameters, loop bindings, let variables and match pattern bindings should be visible in their true lexical scope. Do not expose out-of-scope variables or regress global completions. Partial flag names must yield flag suggestions, including listing flags after a single dash; custom completers must run for values, not flag names. Continue supporting `type@completer` in command signatures/externs, but reject it in variable annotations with `Unexpected custom completer`.

Move completion metadata off `Expression` and onto signature positional arguments and flags, and extend it to support static value-list completions as well as custom commands. The final signature representation must use `completion: Option<Completion>` with an enum supporting custom completion `DeclId` and static values. Update callers/tests coherently; do not leave the AST migration half finished.

`commandline edit --accept`/`-A` must execute the edited buffer immediately with replace, insert and append modes. Add `ReplState.accept: bool`, set it when requested, and reset it after consumption. Unknown flag diagnostics should offer contextual suggestions. Command help flags should have the required-status ordering specified by their semantics. `$nu` must indicate LSP mode and printing must behave appropriately in that mode. Correct the filesize formatting example typo and the broken `query json` documentation link.

Consolidate duplicated LSP tests through reusable parameterized tests while retaining their assertions. Goto definition must work in newly created unsaved documents from the LSP cache, not just files already on disk. Improve script-file-not-found diagnostics to point at the command-line input rather than an internal source location.

## Predictable data and streaming behavior

`overlay list` must return a table with name and active status, include hidden overlays, and use consistent ordering. `overlay use` must correctly register modules in scoped contexts. `detect columns` must never construct invalid records with duplicate keys. `which` without an application argument must list available commands. Register dummy namespace commands for orphaned multiword commands without destroying the real commands.

`get`, `select` and `reject` need `--ignore-case` cell-path access while preserving exact-case default behavior and optional-path semantics. Thread optional/casing parameters through custom value cell-path APIs. `each --flatten` must stream closure results rather than collect the full result first; `each` on a single `null` must be a no-op. Nested `each` errors must propagate through the entire chain rather than disappear. Correct cleanup of error handlers when loop control exits `try` blocks. Commands returning only part of their input must reset content-type metadata instead of asserting that a partial result is still a complete document. `save` must support custom values.

Add table streaming configuration for batch duration and page size. Ensure command example result spans are valid for metadata introspection. `to md` must produce valid markdown tables and support character-escaping options. Quote strings containing `=` when serializing NUON. Add endianness control to `into binary`. Convert CellPath values to string representations. Support complex data in SQLite JSON/JSONB columns for storage and retrieval. Use the terminal's default color for unspecified theme colors.

`str length --chars`/`-c` counts Unicode scalar values in both ordinary and const evaluation, distinct from default UTF-8 bytes and `--grapheme-clusters`. For example `hällo` is 5 chars and 6 bytes. Reject the two explicit counting modes together with `IncompatibleParametersSingle`, update the arguments/signature and switch descriptions consistently. `path relative-to` should try case-insensitive component comparison only after exact prefix matching fails on Windows/macOS, retaining case sensitivity on Linux/FreeBSD. Implement `is_case_insensitive_filesystem()` and `try_case_insensitive_strip_prefix(lhs: &Path, rhs: &Path) -> Option<PathBuf>` in relative_to.rs; compare normal components by lowercase text and other component kinds exactly.

Handle Windows device paths with exported `nu_path::is_windows_device_path`: false on non-Windows; recognize device paths on Windows. Use it to bypass glob expansion in open, treat device paths as existing for save append, bypass canonicalization in source, and return such paths directly from parser `find_in_dirs`.

## XML plugin behavior

`query xml` must return XPath booleans, numbers and strings as native scalar values. Nodesets remain tables with fixed `string_value` columns independent of query length. Add `--output-string-value`, `--output-type` and `--output-names`: without flags return only string_value; with flags return only requested columns, in the order string_value, type, local_name, namespace, prefixed_name. Missing names are nothing. Type values must distinguish element, attribute, text, comment, processing_instruction, root and namespace. Make `xml:` automatically map to http://www.w3.org/XML/1998/namespace without explicit registration. Preserve the four-argument `execute_xpath_query(call: &EvaluatedCall, input: &Value, query: Option<Spanned<String>>, namespaces: Option<Record>) -> Result<Value, LabeledError>` signature: read output flags from call inside the body. Do not break existing positional callers.

## Reusable internals and coherent dependency migrations

Implement optimized `SharedString` and `UniqueString` in `nu-utils::strings`, as a directory module with shared.rs and unique.rs. Both should have small-string optimization, static-literal reuse without allocation, 16-byte layouts on 64-bit systems, and niche optimization so Option has the same size. SharedString must clone shared data cheaply; UniqueString must avoid atomic reference counting. Supply Clone/Debug/Default/Display/Deref/Eq/Hash/Ord/PartialEq/PartialOrd/AsRef<str>/Borrow<str>, serde, constructors from_string/from_static_str/from_fmt, and sformat!/uformat! macros. Ensure the relevant macro is visible unqualified in its implementation module. Add the appropriate workspace byteyarn, lean_string, memchr and serde derive dependencies.

Extract generic `nu_utils::SplitRead<R: BufRead>`, `new(reader, delim: impl AsRef<[u8]>)`, an iterator of Result<Vec<u8>, io::Error>. Support multibyte delimiters split across read buffers, consecutive/boundary empty fields and I/O errors; reject an empty delimiter by debug assertion `delimiter can't be empty`. Keep the old byte_stream.rs split_read module with a re-export so existing callers/tests still compile; avoid duplicated implementation. Add `NuCow<B,O>` Borrowed/Owned with distinct concrete types, transparent untagged serialization, deserialization always to Owned, cross-variant value equality, Debug with alternate variant names and conditional Clone. Export it at nu-utils root. Extract `MultiLife<'out,'local,T: ?Sized>` Out/Local with `'out: 'local`, Deref, export from nu-utils and re-export from nu-protocol::value.

Add `PipelineData::empty()` as const fn and value/list_stream/byte_stream associated constructors with metadata accepting `impl Into<Option<PipelineMetadata>>`. Migrate construction sites across consumers, including engine, CLI and plugin crates, while leaving enum destructuring patterns intact. Refactor command context initialization coherently across callers. Upgrade ureq to 3.x with compatible redirect/error behavior; adapt uutils coreutils from 0.0.30 to 0.2.2, reedline 0.41 to 0.42 and rusqlite 0.31 to 0.37. Use Rust 1.88.0 for the resulting repository. Preserve source-level compatibility of public signatures/fields/exports unless this roadmap explicitly mandates their migration; tests are real callers, not disposable scaffolding.
